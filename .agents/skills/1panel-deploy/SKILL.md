# SkillHub 1Panel 部署

先读[部署规范](../../../.trellis/spec/deployment/index.md)、[部署手册](../../../docs/09-deployment.md)，以及 [1Panel 目标与执行契约](references/targets-and-api.md)。配置契约是本技能新增的接入方式，不表示项目已存在面板或完成过部署。

部署请求授权更新已指定的目标与应用服务；查询、编辑技能不更新。优先使用 1Panel 专用连接器/API，确需界面操作时遵循项目 Computer Use 委派规则。镜像发布使用 [docker-publish](../docker-publish/SKILL.md)，本技能不自动提交或构建。

## 只读查询

用户仅查询部署版本或运行状态时，选定目标后读取编排、现有镜像/容器和健康信息，按实际证据报告并结束。不要求新镜像映射，不执行迁移或部署前置检查，不生成 taskID，不调用 update、强制拉取或重建。某些应用地址未配置时报告相应信息未核实，不能为了查询补写配置。

## 部署执行

1. 检查 Git 忽略规则后，在请求进程内读取 `.1panel.local.json`。按用户或本次 release 已选的目标执行；缺少目标且有多个时询问，不机械要求“对内／对外”两套环境。
2. 缺少镜像参数时询问组件到完整版本镜像的映射，或使用本次已核实的构建结果。不得从 `latest`、本地版本或其他环境猜测。检查目标架构和所有准备更新的镜像；多服务的版本组合必须有兼容依据。
3. 按参考契约取得唯一编排、有效 Compose/env、服务容器及新旧镜像，核对配置/迁移要求。server 启动可能执行 Flyway，涉及迁移须说明备份及兼容证据；缺少必要恢复条件时在写入前报告阻塞，不用启动试错。
4. 仅修改映射中的应用镜像及确需变化的版本环境键；保留其他服务、数据卷、网络、profiles、secret 和配置。核实目标版本 API 的实际拉取/重建服务、profile 和依赖行为，不能从 YAML 未变推断无影响。无法限制在已授权服务范围时，提交前停止并说明具体影响及可选执行方式。更新前说明目标、镜像及重建影响；已授权范围无需再次确认。
5. 为每个目标生成独立 taskID，提交一次并跟踪该任务。超时或结果不明先查任务和容器；失败停止后续目标，不重跑、不自动回滚。
6. 核验最终 Compose、实际容器镜像/digest、运行与健康状态、后端健康接口、Web 入口和本次受影响路径。健康检查和完整业务验收分别报告，不能只凭接口 200 声称全部可用。

多个目标按明确顺序依次执行，复用同一组核实的镜像，各自保留任务、凭据及核验证据；一个失败时保留已完成结果，后续标为未执行。未运行的可选 `github-sync` profile 不自动启用。

## 交付

逐目标报告任务 ID、各组件原/新镜像及容器状态、健康/HTTP 结果、已确认访问地址、实际版本证据与未验证业务。结果区分成功、部分完成、失败、部署完成但核验受阻；失败指出停止步骤和脱敏原因。仅查询时明确无更新。
