# SkillHub 二开变更日志

从仓库根目录执行。记录本地相对已集成上游仍然有效的功能、修复和升级要求。`cli/CHANGELOG.md` 单独维护 CLI 发布历史。

## 选择本次改动

1. 运行 `git status --short --untracked-files=all` 和 `git diff --cached --name-status`。暂存区有变更时，以 `git diff --cached` 为准；同一文件的未暂存修改留待下次。暂存区为空时，读取 `git diff` 和与本次任务相关的未跟踪文件。用户明确指定提交范围时，按该范围分析。
2. 从 diff、相关实现和必要的 Git 历史核实谁受影响、在什么条件下、行为如何变化。过滤上游同步、合并过程、纯上游功能和仅维持原行为的冲突适配。混合改动只提取独立的本地行为。来源不清时指出待确认项。
3. 跳过仅涉及日志维护、Agent 工具、格式、注释或无行为影响的文档与锁文件改动。配置默认值、权限、部署和兼容性变化按实际影响判断。没有符合条件的改动时，说明跳过原因并结束。

## 按功能更新

先通读 `changes/CHANGELOG.md` 和候选条目的详情。按用户可观察的行为拆分独立改动，同一功能横跨 `server/`、`web/`、`cli/` 时合为一条。共享翻译、配置或同一目录可帮助定位候选项，最终依据功能语义判断。

- **已有功能**保留编号，更新日期、说明、相关文件和详情。用中文写当前最终行为，保留仍有效的默认值、权限、回退、迁移及兼容要求。
- **撤销或替代**时核实代码是否迁移或改名。部分撤销只清除失效部分；完全撤销且没有本地差异或遗留影响时，删除该条。删除上游原有能力属于有效本地差异。证据不足时保留原记录。删除详情前检查剩余内容及其他引用。
- **独立的新功能**在表末追加。取现有最大编号加一，从 `001` 开始，至少三位，保留其他条目的编号。

## 写入格式

首次有可记录的改动时创建 `changes/CHANGELOG.md`，使用以下表头。日期取执行当天的 `YYYY-MM-DD`。

```markdown
# SkillHub 二开变更日志

| 编号 | 日期 | 说明 | 详情 |
| --- | --- | --- | --- |
```

说明用一句中文写清行为。涉及一至三个文件，在详情列用反引号标记仓库相对路径，以顿号分隔。超过三个文件时，创建 `changes/details/{编号}-{英文短标识}.md`，在索引使用相对链接，如 `[详情](details/001-cli-login.md)`。详情写中文标题、日期、当前行为及约束，并逐项列出文件路径与职责。更新已有条目时同步核对文件数量、路径和链接。

## 验证与交付

检查本次编号唯一、索引与详情一致、链接可达。复查 `git diff -- changes/` 和新文件内容。按参考工作流使用 `git add -- <本次日志路径>` 暂存本次生成、修改或删除的日志。若同一日志文件已有用户编辑，单独暂存本次差异；无法可靠分离时保留暂存状态并说明。用 `git diff --cached --check -- changes/` 检查格式，向用户报告新增、合并、消除或跳过的结果，以及对应编号、说明和暂存状态。
