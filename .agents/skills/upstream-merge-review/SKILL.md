# SkillHub 上游合并交接

默认只读，不修改代码、日志或 Git 状态。读取[工程入口](../../../.trellis/spec/index.md)及受影响领域正文，结合[测试入口](../../../.trellis/spec/testing/index.md)判断证据范围。

## 依据

优先使用用户或当前任务指定的 merge commit。核实它的两个父提交分别是什么，固定合并前本地、上游及共同基线；多父提交或非 merge commit 时先说明不适用的比较模型，不能虚构双父关系。

比较基线到上游、合并前本地到目标 merge commit，区分上游提出的变化与最终实际接入。读取目标提交中的相关源码、调用方、配置、`changes/CHANGELOG.md` 和详情；不存在日志则改用历史和实现，不能认定无定制。功能结论始终以目标版本为准，不混入当前 HEAD 或未提交修改。

决策和验证使用任务记录、会话或本次实际执行证据，不能从最终 diff 推断曾获确认或测试通过。当前分支、冲突、推送和清理状态另行实查，并注明观察时间。

## 交付

中文直接输出，先说明关键行为变化，再按实际复杂度组织以下内容；无则写无或不适用：

- 来源、目标、固定提交与当前 Git 状态；提交、远端同步及清理是否完成。
- 实际接入的新能力、修复、结构、API、配置和依赖变化，区分上游范围与最终接入范围。
- 用户可见的页面入口、布局、文案、状态反馈和操作流程变化，说明角色及最终采用的实现；没有则明确“无用户可见的 UI 变化”。
- 本地定制及关联日志编号的保留、兼容适配或缺口，附关键代码依据。
- 冲突与双方修改文件的取舍、舍弃的上游内容、影响及决策来源；无法核实的确认记录明确标注。
- 检查通过、失败、未运行和环境受阻分别报告。构建、容器健康、业务 Smoke 的证据不互相替代。
- 配置、Flyway 迁移、备份与兼容要求；必要的人工验证给出前置条件、步骤、预期和失败判定。
- 剩余阻塞、未授权操作与明确下一步。

不另建报告文件，除非用户要求保存。发现缺陷说明证据和影响，不自动修复；合并未完成时仅交付阶段发现。
