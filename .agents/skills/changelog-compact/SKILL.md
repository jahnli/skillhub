# SkillHub 二开记录整理

从仓库根目录工作，读取[工程入口](../../../.trellis/spec/index.md)和 [changelog](../changelog/SKILL.md)。只整理 `changes/`，不改业务代码或 `cli/CHANGELOG.md`。用户只要求预览时输出方案；要求整理时直接编辑，默认不暂存、提交或推送。

## 核实和整理

1. 检查 Git 状态，通读主索引，按功能读取相关详情全文。目录不存在时说明没有可整理记录，不创建空日志。
2. 结合当前代码、调用方、配置和历史确认能力及约束。记录与实现不符时指出冲突；路径消失先查改名、搬迁或替代，不能凭关键词未命中删除记录。
3. 判断是否仍是二开差异时，固定当前已集成的上游基线。未集成的最新上游不能作为删除依据；来源不清时保留记录并说明。
4. 按功能语义合并同一能力，不因共用文件或目录合并独立主题。改写为当前最终行为，保留角色、权限、默认值、拒绝与失败分支、配置、审计、迁移及兼容要求。
5. 本地新增后完全撤销、没有残余影响且相对已集成上游无差异时，消除新增及撤销描述。部分撤销只清除相应部分；本地删除上游能力仍是有效差异。上游已覆盖的功能须确认本地确已集成且语义等价才移除。
6. 清除纯上游同步和合并过程记录。证据不足的条目保留，不用泛化措辞替代具体业务值。

## 编号和详情

保留原编号及空缺，不重排、不新增功能编号。合并时保留代表主题的原编号，修复 `changes/` 内引用；发现范围外引用时保留可用入口并报告，除非用户另行授权修改。

纯文字整理不更新业务日期。合并日期取有证据的最终行为变更日期，无法核实时保留。同步索引、详情和文件清单；只删除专属于失效条目、无剩余内容且无其他引用的详情，共享详情只删相关部分。

## 交付

检查编号唯一、链接、残留引用和 `git diff --check -- changes/`；新文件另查内容。仅做文档检查，不触发业务测试。报告合并和消除的主题、保留的关键约束、证据不足项目及暂存状态。
